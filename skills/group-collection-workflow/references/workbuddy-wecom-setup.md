# WorkBuddy 企业微信配置与验收

用于引导使用者接入和确认，不代表已获配置、发消息或改权限的授权。界面和账号能力可能变化，执行前核对当前版本与官方说明。

## 先问最少的问题

确认使用者是否有企业微信账号、谁管理机器人、是否已有绑定、成员使用企业微信还是个人微信、目标群及在线表是否已经存在。已有答案不重复问。

先核对现有机器人身份和 WorkBuddy 绑定，名称相同不证明是同一个。把机器人、群、项目与表格的对应关系保存在私密项目配置，不放公开技能。复用前确认机器人未承担其他不能中断的业务。

已有成功记录、换项目或掉线恢复时，先读[已有系统接手与恢复](existing-system-and-recovery.md)，定向查入口和必要证据。不要因本地业务目录缺接收服务代码，就断言连接器没有执行链；也不因找到了归档WebSocket或CLI描述，就声称当前版本支持相同能力。

## 常见接入路径

官方指南描述的常见方式为：WorkBuddy 的助理设置中打开企微集成，选择长连接，填写对应机器人的 Bot ID 和 Secret 后注册；也提供企微扫码快捷绑定。企业微信侧须使用与之匹配的 API 接入模式。入口以当前界面为准。

- 已有机器人优先评估复用。快捷绑定可能创建新机器人，不以“重新绑定”为由未经批准重复创建。
- 只有没有合适机器人且用户批准时，才按官方流程创建。需要登录、扫码、授权或管理员批准时，指出具体入口、所需权限与影响，等待人工完成；不代替用户批准。
- 若现有方式正常，不强制改成长连接。URL 回调为另一种接入方式，凭据和配置不同，不能混填；不顺带部署公网服务。
- Secret 仅在官方配置界面或获准的秘密存储中处理。截图遮盖秘密，不把明文写入聊天、规则、日志、公开仓库或备份说明。不得未经批准重置 Secret；重置会要求同步更新使用它的连接端。

## 三层权限分别确认

1. **成员能否使用机器人**：检查机器人可见/使用范围及群内支持条件。由管理者只授权需要的成员；不默认全公司。个人微信与企业微信不是同一种身份，不承诺外部微信成员一定能使用，须按实际群类型和平台能力实测。
2. **机器人能否执行操作**：按需要检查消息、对话用户信息、文档等能力授权，优先最小范围。授权入口通常可从企微工作台的智能机器人详情或当前平台提示进入；角色与版本不同，不能把机器人一律当作“自建应用”。已授权不保证当前连接有效或授权仍有效，须看当前状态及调用结果。
3. **能否访问指定文件**：文档能力授权不等于拥有目标文件权限。核对文档真实类型、所属账号、具体读写和导出权限；不通过给所有报账成员文档权限解决机器人写入问题。收入、利润与全员明细仅给批准人员。

## 获准后分层验收

先明确测试账号、群、表和允许的动作；没有授权只给步骤，不发消息或建测试对象。

- 单聊：简单测试消息确实进入正确 WorkBuddy 会话，并回复到原会话。
- 群聊：获准测试群中的普通成员 @ 机器人，核对原 senderId、群路由及回群结果；管理员单聊成功不能替代这一项。
- 业务：模拟提交→草稿→确认→测试表写入→涉及行读回；重复发送不重复记录，人员不串，手机格式可读。
- 隐私：未经授权账号无法查看敏感表或获取经营数据；授权错误和技术日志不发业务群。
- 运行：记录执行端所在电脑、服务状态和重启后连接结果。本地端关闭不承诺继续处理；用户选择自动恢复补读或指令补读后，分别验收启动检测、连接恢复、历史覆盖、附件读取及跨重启确认。扫描进度与业务完成进度不能混用。

以上分别记录“已通过（附证据）／失败／待测”，不使用一个“已绑定”代替全部通过。只在全部必要项通过且用户批准后接正式业务。

## 不响应时的排查顺序

先看执行端运行与连接状态，再查接入方式、机器人身份及凭据是否匹配（不回显秘密）、网络、成员使用范围、消息是否投递到其他会话。消息能到但写表失败时，再查文档授权与文件权限；不要首先新建机器人。

模型限流、积分不足、授权过期、消息未投递和写表失败是不同问题，应说明证据与最小修复。无法确认就标待核实，不承诺已修好。
